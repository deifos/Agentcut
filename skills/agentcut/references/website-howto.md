# Website how-to execution

Use this reference to prevent stalled work during website walkthroughs, setup tutorials and
feature videos. Keep the main skill's creative process and full review. Do not reduce formats,
UI detail, animation, voice, music, sound design or review coverage to save time. User instructions
and existing project choices take priority.

## Reuse working setup

Read `references/efficient-review.md` for grouped independent file/guide reads and changed-shot
revision checks. Use scoped plans only for intermediate work; retain full final picture/sound
review and broaden when shared components, media or timing affect other shots.

- Start from the known app URL, source folder and existing project notes. Reuse a working
  preview, app build, captured evidence and generated assets when they are still current.
- Ask for a missing source location instead of searching the entire home folder and GitHub.
- When source-based UI work improves the result, keep it. Check that it matches the current
  app, and do not invent product behavior. Preserve approved demo disclosures.
- Keep the script and shot list within the requested duration. Preserve the craft steps for
  both formats, music selection, sound design, voice checks and visual review.

## Recover from stalled tools

- Run page-heavy checks one at a time: frame captures, contact sheets, playback checks,
  audio analysis/listening and exports. Do not launch wide and mobile sheets and audio
  critique concurrently. Complete the same checks in sequence.
- A tool timeout does not prove the browser stopped the work. Check
  `agentcut_status.page.activeWork` before retrying. If the earlier task remains active,
  do not add another request, even with fewer frames. Status calls remain available.
- If `activeWork` is unavailable on an older editor, treat timed-out work as possibly active.
  Inspect the page and report the stall. Save pending edits before a reload to clear stuck work.
  Do not repeatedly open and close browser windows.
- After recovery, run one small frame probe. This checks that rendering works; it does not
  replace full-resolution inspection, contact sheets, both-format review or playback checks.
  Resume the full review once the probe succeeds. Keep final render quality unchanged.
- If the probe also stalls, preserve the project and report the blocked check. Do not add
  another series of five- or ten-minute waits. The review remains incomplete until it passes.
- An unknown `studio.local.*` method can mean that the MCP server and running helper differ.
  Report the required update or restart rather than repeating the same failed method. The
  release-job prototype supports announcement only; how-to uses the direct studio workflow.
- Give a clear progress update when a phase stalls. State which check is blocked and what
  is complete. Do not claim that a build proves the video is ready.

The goal is to remove idle waits, duplicate setup and competing checks while preserving the
quality of the final video. These changes do not promise a fixed completion time.
